## PART 3 — Referrals (full backend + frontend)

### Backend
- **New table** (`database.js`): `referrals` — `{ id (uuid), user_id, referral_code (UNIQUE), created_at }`; `referral_events` — `{ id, referral_id, type (click|signup|convert), visitor_ref, created_at, metadata jsonb }`. Idempotent code generation (user initials + random, unique-retry).
- **Endpoints** (`index.js`):
  - `GET /api/referrals/code` — returns/creates the user's referral code + shareable link (`https://<host>/?ref=<code>`).
  - `POST /api/referrals/track` — public (unauth) endpoint hit when a visitor lands with `?ref=<code>`; records a `click` event.
  - `GET /api/referrals/stats` — for the referrer: total clicks, signups, conversions, and a list of recent referrals (by code, privacy-safe — no PII of referees shown).
- **Signup attribution**: when a new user registers with `?ref=<code>` in their session, record a `signup` event (and `convert` if/when they hit a paid plan). Wire into the existing signup flow.
- **Validation** (`validation.js`): referral code shape.

### Frontend
- Add `"Referrals"` to `settingsCategories` (`App.jsx:5202`).
- New panel block `{activeSettingsPanel === "Referrals" && (...)}`: shareable link + copy button + QR (optional), and stat cards (clicks / signups / conversions) + recent-referrals list.
- New service client `utils/referralApi.js` (`getReferralCode`, `trackReferral`, `getReferralStats`).
- On app load, if `?ref=` present, call `trackReferral` once (store in sessionStorage to avoid double-count).
