# Zenin dashboard critique — 2026-07-18

## Overall

**27/40 — focused Home hierarchy, incomplete system migration.** The live Home route now makes the portfolio’s health legible in one scan: value, performance, risk, signals, then context. The shared header/metric/signal primitives are a meaningful step forward. The main gap is consistency: several other dashboard routes retain their older dense-control/card composition, and legacy CSS still leaks visual patterns that the new system explicitly rejects.

## What works

- The current Home scan order is clear: portfolio value, return, risk posture, actionable signals, performance history, then market and position context.
- Risk is now compositional rather than decorative: the Risk Monitor is adjacent to the featured portfolio state and semantic status includes text, not color alone.
- The removal of the duplicate desktop toolbar is correct. It restores attention to the workspace instead of repeating search, upgrade, help, expand, and account controls above every route.
- The sidebar keeps the broad product understandable and exposes clear state through the active navigation item.

## Priority issues

### P1 — Finish the shared-composition migration across every dashboard surface

The new primitives are live on Home and Portfolio, while Watchlist and many specialist routes still rely on their earlier card- and chip-heavy compositions. This creates two interaction languages in one product: the newer routes answer “what matters now?”; the older routes make users decode controls before they can read the decision state.

**Next move:** migrate each route to `WorkspacePageHeader → featured decision state → primary analysis/table → ContextRail`, beginning with Watchlist, Intelligence, Analytics, and Options. Treat the existing route content as data sources rather than preserving legacy panel shells.

### P1 — Reduce first-viewport control density on specialist pages

The earlier live Watchlist view exposed multiple equal-weight market-type toggles, visual-mode buttons, import/refresh controls, threshold input, and many topic chips before the one-row watchlist table. The task (“inspect the names I track”) arrives too late and the page makes filtering look like the primary job.

**Next move:** keep a single default scope visible; place secondary filters in an overflow/filter drawer; let the tracked table or ranked action list begin within the first viewport. Make import a contextual empty-state or table action, not a peer of browse controls.

### P1 — Eliminate remaining thick side accents and competing card languages

The deterministic scan still finds 12 thick left-border accents in `styles.css` and `styles/intelligence.css`. These fight the new semantic system by making every panel look equally urgent. Several remain attached to neutral/structural elements, where the accent has no state meaning.

**Next move:** replace each with a 1px semantic border, tinted surface, or status badge/icon. Reserve elevated surfaces only for featured decisions or explicit interaction; open up ordinary content with dividers and typography.

### P2 — Make stale/failed financial data explain the practical consequence

Home announces “Showing last confirmed data” and carries individual `CACHED`/missing-data states, but the user still has to infer which decisions are affected and what they can do next. This is especially important on a financial desk where a plausible stale value can feel deceptively authoritative.

**Next move:** standardize every freshness message as `status → implication → last confirmed → action`, e.g. “Prices last confirmed 18:51; allocation may exclude six assets. Review gaps.”

### P2 — Use contextual help consistently, not only in the new metric strip

The risk rail names beta, theta, implied volatility, breadth, regime, and alignment, but explanatory help is uneven outside Home/Portfolio. Newer users can see a risk color without being able to judge its meaning.

**Next move:** attach `MetricHelp` at first exposure on Analytics, Options, Intelligence, and Tax, then keep repeat appearances compact. Pair each risk state with one short “why this matters” sentence.

## Personas

- **Alex, active investor:** gets a fast read on Home but loses time switching to Watchlist/Options, where controls precede the decision surface. He needs a saved default and table-first composition.
- **Jordan, newer investor:** sees clear return and warning status but still needs definitions and implications for Beta, Theta, IV, and stale data before trusting the dashboard.
- **Riley, cautious long-term investor:** benefits from the risk rail and text-labelled warning, but needs data freshness to specify exposure/decision impact rather than merely announce staleness.

## Minor observations

- The `Geist Mono` detector hits are mostly appropriate for compact financial figures; they are not a design priority.
- The remaining `transition: width` in `public.css` risks a small layout jank during state changes; use transform or opacity when possible.
- The “First account / Connect a read-only source” card is useful but competes with the live portfolio state when account data already exists; demote it after connection or make it a contextual task.
